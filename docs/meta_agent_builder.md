# Meta Agent Builder

## Introduction

The Meta Agent Builder feature allows users to define and create new, fully functional AI agents by describing their desired capabilities in natural language. This provides a flexible way to quickly prototype and deploy specialized agents without writing extensive configuration code manually.

## Core Components

The system relies on several key components working together:

### 1. `MetaAgent`

*   **File**: `src/agents/meta_agent.py`
*   **Description**: The `MetaAgent` is a specialized agent that serves as the "agent creator." Its primary role is to interpret a user's natural language prompt describing the desired new agent. Based on this prompt, the `MetaAgent` generates a structured configuration object.
*   **Input**: A natural language string describing the new agent (e.g., "I need an agent that can tell me the weather and calculate things").
*   **Output**: An instance of `NewAgentConfig`.

### 2. `NewAgentConfig`

*   **File**: `src/agents/config_models.py`
*   **Description**: This Pydantic model defines the structured configuration for a new agent. The `MetaAgent` populates this model.
*   **Fields**:
    *   `name` (str): The desired name for the new agent (e.g., "WeatherMathHelper").
    *   `instructions` (str): The system prompt or detailed instructions that will guide the behavior of the new agent.
    *   `model_name` (str, default: "o3-mini"): The specific AI model the new agent should use (e.g., "o3-mini", "gpt-4").
    *   `tool_names` (List[str], default: []): A list of names of pre-existing tools that the new agent should have access to.

### 3. `build_agent_from_config`

*   **File**: `src/agents/agent_builder.py`
*   **Description**: This function takes the `NewAgentConfig` object (generated by the `MetaAgent`) and constructs an actual `Agent` instance. It resolves the tool names listed in the config against the `AVAILABLE_TOOLS` dictionary and initializes the agent with the specified name, instructions, model, and resolved tools.

### 4. `AVAILABLE_TOOLS`

*   **File**: `src/agents/agent_builder.py`
*   **Description**: This dictionary contains the pre-defined tools that the `MetaAgent` can choose from when configuring a new agent. Users should be aware of these tools to effectively request agents that use them.
*   **Currently Available Tools**:
    *   `get_current_weather`: "Gets the current weather for a specified location."
    *   `simple_calculator`: "A simple calculator that can evaluate basic arithmetic expressions (+, -, *, /)."
        *   *Note*: The `simple_calculator` uses `eval()` for simplicity and includes a security warning. For production use, a safer parsing mechanism is recommended.

## How to Use

The primary way to interact with the Meta Agent Builder is demonstrated in the example script: `examples/meta_agent_builder/run_builder.py`.

The general flow is as follows:

1.  **Provide a Prompt**: A user formulates a natural language request detailing the kind of agent they want to create. This prompt is given to the `MetaAgent`.
    *   It's helpful to mention the desired name, tasks, any specific AI model, and the names of any tools from `AVAILABLE_TOOLS` that the new agent should use.
2.  **`MetaAgent` Generates Configuration**: The `MetaAgent` processes this prompt and outputs a `NewAgentConfig` object.
    *   **Important**: The `MetaAgent` itself (and potentially the agents it creates, if they use OpenAI models) requires the `OPENAI_API_KEY` environment variable to be set to a valid OpenAI API key.
3.  **Build the Agent**: The `build_agent_from_config` function takes the generated `NewAgentConfig` and creates an instance of the new agent.
4.  **Use the New Agent**: The newly built agent is now ready to be used like any other agent, taking inputs and performing tasks based on its configuration and tools.

### Example User Prompt for `MetaAgent`

Here's an example of what a user might provide as input to the `MetaAgent`:

```
"I need an agent that can tell me the weather and also perform simple calculations.
Please call it 'WeatherAndMathPal'. It should be friendly and use the 'o3-mini' model.
Make sure it has access to the 'get_current_weather' tool and the 'simple_calculator' tool."
```

The `MetaAgent` would then attempt to generate a `NewAgentConfig` with:
*   `name`: "WeatherAndMathPal" (or similar)
*   `instructions`: A friendly instruction set for weather and math tasks.
*   `model_name`: "o3-mini"
*   `tool_names`: ["get_current_weather", "simple_calculator"]

## Limitations & Future Ideas

The Meta Agent Builder is a powerful tool for agent prototyping, but it has several areas for potential future enhancements:

*   **Predefined Tool Registry**: Currently, the `MetaAgent` can only equip new agents with tools from the centrally defined `AVAILABLE_TOOLS` list. Future work could involve mechanisms for an expanded or user-defined tool registry, allowing users to register their own custom tools more easily.
*   **Dynamic Tool Creation**: The system does not yet support creating brand new tools (e.g., generating Python code for them) on the fly based purely on user descriptions. This is a significant area for future research, where the `MetaAgent` could not only configure an agent but also help define or generate the code for new, bespoke tools.
*   **Advanced Agent Configuration**: The current `NewAgentConfig` supports core agent properties (name, instructions, model, tools). Future versions could allow the `MetaAgent` to configure more advanced aspects, such as:
    *   Defining specific output types for the new agent (beyond simple text).
    *   Configuring inter-agent handoffs.
    *   Specifying detailed model settings (e.g., temperature, custom API parameters).
*   **Configuration Persistence**: Generated agent configurations are currently ephemeral. Adding functionality to save a `NewAgentConfig` to a file (e.g., JSON or YAML) and later load it to rebuild an agent would be highly beneficial for reusability.
*   **Interactive Building Flow**: The agent creation process is currently a single-shot interaction with the `MetaAgent`. A more interactive or conversational flow could allow for refinement of the agent's configuration through dialogue, leading to more precise and tailored agent creation.
